# Daily Bulletin Reliability

## Contract

The Daily QuantBet bulletin remains generated by `.github/workflows/daily.yml`. The watchdog does not contain generation, selection, API, risk, or email-generation logic.

## Flow

```text
00:51 Europe/Belgrade
    daily.yml
       |
       +--> guard: today's bulletin_health.json == SUCCESS?
       |       |
       |       +--> yes: NO-OP
       |       +--> no: existing generate -> commit -> send-report -> success marker
       |
~01:05 Europe/Belgrade
    bulletin-watchdog.yml
       |
       +--> success marker present: NO-OP
       |
       +--> missing: gh workflow run daily.yml --field force=false
                         |
                         +--> existing daily path
                         +--> wait for recovery result
```

## Canonical marker

`bulletin_health.json` is the canonical production marker. A `SUCCESS` marker is valid only when all of these are true for the current `Europe/Belgrade` business date:

- `generation_status == SUCCESS`
- `commit_status == SUCCESS`
- `send_status == SUCCESS`
- `status == SUCCESS`
- `completed_at` exists

The marker also records generation timestamps, workflow run ID/attempt, workflow SHA, and timezone.

The marker is written only after `generate --no-email`, the ledger/raw API commit, and `send-report` have succeeded. It is then committed as the final completion record.

## Idempotency and races

`daily.yml` retains the shared `quantbet-ledger` concurrency group. Its first guard makes a later invocation a no-op when the current business date already has a successful marker. This protects the case where the scheduler is merely delayed and a watchdog recovery is queued behind it: whichever daily run completes first writes the marker, and the later run exits without generating or sending another bulletin.

Manual `workflow_dispatch` supports `force=true` for an intentional new bulletin run; the watchdog always uses `force=false`.

## Scheduler limitation

GitHub documents that scheduled workflows can be delayed during high load and that some queued jobs can be dropped. The watchdog therefore provides an independent scheduled check rather than assuming the primary schedule is infallible.
